ENSEMBLE CAST 起動コマンド
==========================

■ 起動（WSL ターミナルから）
  ensemble          … ensemble セッション起動（Producer/Director/Cast ペイン作成）
  ens-couch         … シアターモード（LIVE画面 + 観戦用Commentary）

■ 再接続（ターミナルが落ちた場合）
  ens               … ensemble セッションに attach
  ens-couch         … theater セッションに attach

■ シアター内の管理メニュー
  Ctrl+b → Shift+M  … 管理メニュー表示（再起動/状態確認/チェックポイント）

■ 手動コマンド
  bash scripts/ensemble-ctl.sh restart        … 全体再起動
  bash scripts/ensemble-ctl.sh restart-live   … LIVE画面のみ再起動
  bash scripts/ensemble-ctl.sh status         … 状態確認
  bash scripts/ensemble-ctl.sh checkpoint     … チェックポイント保存

■ Theater Web UI（ブラウザで鑑賞）
  ens-couch 起動時に自動でサーバー起動 + ブラウザオープン（http://localhost:3939）
  python3 scripts/theater-server.py  … サーバーのみ手動起動したい場合

■ Chrome DevTools（Cast によるブラウザ自動テスト用）
  WSL 上の Cast が Chrome を操作してブラウザテストを行うためのプロセス。
  DevTools Protocol (port 9222) 経由で WSL → Windows Chrome に接続する。

  起動（Windows の PowerShell / cmd / Git Bash から）:
    start chrome --remote-debugging-port=9222 --user-data-dir="%TEMP%\chrome-debug"

  確認:
    curl -s http://localhost:9222/json/version

  前提条件:
    - .wslconfig に networkingMode=mirrored が必要（WSL↔Windows localhost疎通）
    - WSL 側に chrome-devtools-mcp がグローバルインストール済み（/usr/bin/chrome-devtools-mcp）
    - ~/.claude.json に MCP サーバー設定済み（env.PATH で Windows PATH 除外）

  注意:
    - 通常の Chrome とは別プロファイルで起動される（--user-data-dir 指定）
    - 拡張機能・ブックマーク等は空の状態
    - ensemble 終了後も Chrome は手動で閉じる必要あり

■ 起動順序（初回 or ターミナル完全再起動時）
  0. Chrome DevTools ← Windows 側で先に起動（Cast のブラウザテストに必要）
  1. ensemble       ← まずこれ
  2. ens-couch      ← 次にこれ（別ターミナルタブ推奨。Web UIも自動起動）
